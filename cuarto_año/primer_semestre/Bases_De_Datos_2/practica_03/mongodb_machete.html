📄 Un documento (BSON)

{
  _id: ObjectId("..."),   // PK automática
  nombre: "City Tour",
  precio: 200,
  totalKm: 5,
  stops: ["Diagonal Norte", "Plaza Mayo"],
  tags: ["urbano", "historico"]
}

BSON = JSON binario. Schemaless: cada documento de una colección puede tener campos distintos.

Clave: una colección no exige esquema fijo (a diferencia de una tabla). Se puede activar Schema Validation opcional a nivel de colección (sección 6).

2 · Modelado: embebido vs referencias

embebido Anidar dentro del documento

{ nombre: "City Tour",
  stops: [                      // ← anidado
    { nombre: "Obelisco", orden: 1 },
    { nombre: "Congreso", orden: 2 }
  ] }
  • Lectura rápida: todo en 1 consulta
  • Atomicidad a nivel documento
  • Ideal: relación 1-a-pocos, datos que se leen juntos y no se comparten

referencia Guardar el _id del otro

{ nombre: "City Tour",
  stopIds: [                    // ← guardo ids (tipo FK)
    ObjectId("a1"), ObjectId("b2")
  ] }
// los stops viven en otra colección
  • Datos compartidos o que crecen sin límite
  • Relación muchos-a-muchos
  • Requiere "JOIN manual" con $lookup
  • Sin validación automática de la FK
Regla: embebés lo que se lee junto y pertenece al documento; referenciás lo independiente, compartido o que crece sin tope. Es el mismo criterio que composición vs asociación.

3 · CRUD básico

insertOne / insertMany
Insertar uno o varios documentos.
db.recorridos.insertOne({ nombre: "City Tour", precio: 200 })
db.recorridos.insertMany([ {…}, {…}, {…} ])
find / findOne
Buscar. find devuelve cursor; .pretty() indenta.
db.recorridos.find()                       // todos
db.recorridos.find({ precio: 200 })          // filtro
db.recorridos.findOne({ nombre: "City Tour" })
db.recorridos.find({}, { nombre: 1, _id: 0 }) // proyección
countDocuments
Contar documentos (de la colección o de un filtro).
db.recorridos.countDocuments()
db.recorridos.countDocuments({ precio: { $gt: 100 } })
updateOne / updateMany
Actualizar. Necesita un operador ($set, $inc…).
db.recorridos.updateOne(
  { nombre: "City Tour" },           // filtro
  { $set: { totalKm: 12 } })          // cambio

db.recorridos.updateMany(
  {}, { $inc: { precio: 50 } })       // +50 a todos
operadores de update
Modifican campos/arrays dentro del update.
$set   { $set: { precio: 300 } }       // asigna
$inc   { $inc: { precio: 50 } }        // incrementa
$push  { $push: { tags: "nuevo" } }    // agrega a array
$pull  { $pull: { tags: "viejo" } }    // quita de array
$unset { $unset: { totalKm: "" } }     // elimina campo
deleteOne / deleteMany
Eliminar documentos.
db.recorridos.deleteOne({ nombre: "Temporal" })
db.recorridos.deleteMany({ precio: { $lt: 50 } })

4 · Operadores de consulta

⚖️ Comparación

$eq  igual          $ne  distinto
$gt  mayor          $gte mayor o igual
$lt  menor          $lte menor o igual
$in  en lista       $nin no en lista
db.recorridos.find(
  { precio: { $gte: 50, $lte: 200 } })

🔗 Lógicos

$and  $or  $not  $nor
db.recorridos.find({ $or: [
  { precio: { $gt: 100 } },
  { totalKm: { $gt: 10 } }
] })

📦 Elemento / Array

$exists  el campo existe
$type    tipo del campo
$size    tamaño del array
$all     contiene todos
// rutas con más de 5 stops
db.recorridos.find(
  { "stops.5": { $exists: true } })

// que NO tengan totalKm definido
db.recorridos.find(
  { totalKm: { $exists: false } })
Array por valor: db.recorridos.find({ stops: "San Telmo" }) matchea si el array contiene ese valor (no hace falta operador).

5 · Aggregation Framework

Un pipeline: el output de cada etapa es el input de la siguiente. db.coll.aggregate([ etapa1, etapa2, … ])

$match
Filtra documentos (como el WHERE). Conviene ponerlo primero.
{ $match: { precio: { $gte: 90000 } } }
$group
Agrupa y aplica acumuladores ($sum, $avg, $max…).
{ $group: {
   _id: "$tipo",                // clave de grupo
   total: { $sum: 1 },           // cuenta
   precioProm: { $avg: "$precio" }
}}
$project
Elige / renombra / calcula campos (como el SELECT).
{ $project: { nombre: 1, _id: 0,
   cantStops: { $size: "$stops" } } }
$sort · $limit · $skip
Ordenar, recortar y saltear.
{ $sort: { precio: -1 } }   // desc
{ $limit: 3 }
{ $skip: 10 }
$unwind
"Desarma" un array: una copia del doc por cada elemento.
{ $unwind: "$stops" }
// 1 ruta con 3 stops → 3 documentos
$lookup
"JOIN" con otra colección (resuelve referencias).
{ $lookup: {
   from: "stops",            // otra colección
   localField: "stopIds",
   foreignField: "_id",
   as: "stopsData"            // array resultado
}}
$sample · $count · $out
Muestra aleatoria · contar · guardar en colección.
{ $sample: { size: 5 } }    // 5 al azar
{ $count: "total" }
{ $out: "rutas_economicas" }  // guarda el resultado

🧪 Ejemplo completo — top 3 rutas más caras, solo nombre y precio

db.recorridos.aggregate([
  { $match:   { precio: { $gt: 0 } } },        // 1. filtrar
  { $sort:    { precio: -1 } },               // 2. ordenar desc
  { $limit:   3 },                         // 3. top 3
  { $project: { nombre: 1, precio: 1, _id: 0 } } // 4. elegir campos
])

6 · Índices y validación

⚡ Índices (aceleran lecturas)

db.recorridos.createIndex({ nombre: 1 })      // 1 asc, -1 desc
db.recorridos.createIndex({ nombre: 1, precio: -1 }) // compuesto
db.recorridos.createIndex({ email: 1 }, { unique: true })

Tipos: simple, compuesto, multikey (sobre arrays), de texto, geoespacial. El unique además valida que no haya duplicados.

Aceleran lecturas pero encarecen escrituras (hay que mantenerlos) y ocupan espacio. Solo sobre campos usados en filtros/orden.

✅ Schema Validation (opcional)

db.createCollection("recorridos", {
  validator: { $jsonSchema: {
    bsonType: "object",
    required: ["nombre", "precio"],
    properties: {
      precio: { bsonType: "number", minimum: 0 }
    }
  }}
})

Impone estructura, tipos y valores a nivel de colección. Es opcional (schemaless por defecto). Valida un documento; la unicidad entre documentos la da el índice unique.

Para tener clarísimo en el parcial: colección=tabla, documento=fila, campo=columna; embebido vs referencias (cuándo cada uno); el pipeline de aggregation ($match → $group → $project → $sort → $limit, más $lookup y $unwind); y que MongoDB es schemaless con validación y atomicidad por documento (transacciones multi-documento desde la v4.0).
