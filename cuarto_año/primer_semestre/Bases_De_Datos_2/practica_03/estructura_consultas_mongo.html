MongoDB — anatomía de las consultas

Cómo se arma cada parte de un find, un update y un pipeline de aggregate

1 · Anatomía de un find()

▸ El filtro elige qué filas; la proyección elige qué columnas (1 = incluir, 0 = excluir). Los dos argumentos son opcionales: find() trae todo.

2 · El filtro: bloques de construcción

Un filtro es un objeto { }. Se arma combinando estos 4 patrones:

① Igualdad simple

{ precio: 200 }

campo = valor. "precio igual a 200".

② Con operador

{ precio: { $gt: 100 } }

campo cumple una condición. Los operadores empiezan con $ ($gt, $in, $exists…).

③ Varias condiciones (AND implícito)

{ precio: { $gte: 50 },
  totalKm: { $gt: 10 } }

Varios campos en el mismo objeto = todos deben cumplirse (AND).

④ OR explícito

{ $or: [
    { precio: { $gt: 100 } },
    { totalKm: { $gt: 10 } }
] }

$or/$and reciben un array de sub-filtros.

3 · Operadores más usados

Van dentro del filtro: { campo: { $op: valor } } (salvo los lógicos, que agrupan sub-filtros).

⚖️ Comparación

$eq  igual        $ne  distinto
$gt  mayor        $gte mayor/igual
$lt  menor        $lte menor/igual
$in  en lista     $nin no en lista

🔗 Lógicos

$and  todas se cumplen   → [array]
$or   al menos una       → [array]
$nor  ninguna se cumple  → [array]
$not  niega UN operador  → { $op }

$and/$or/$nor reciben un array. $not envuelve un operador, no un array.

🔎 Elemento

$exists  el campo existe (true/false)
$type    el tipo del campo

📦 Array

$all   contiene TODOS los dados
$size  cantidad exacta de elementos
$elemMatch  un elemento cumple varias

4 · Consultas sobre arrays (ej. stops)

El caso más confuso. Sobre un campo array como stops: ["Recoleta", "Congreso"]:

✅ Contiene un valor

{ stops: "Recoleta" }

matchea si el array incluye "Recoleta". Sin operador.

🚫 NO contiene un valor

{ stops: { $ne: "Plaza Italia" } }

el array no incluye ese valor. Se usa $ne, no $not.

Contiene TODOS

{ stops: { $all: ["Recoleta", "Congreso"] } }

incluye Recoleta y Congreso (en cualquier orden).

No contiene NINGUNO

{ stops: { $nin: ["A", "B"] } }

no incluye ni A ni B.

Cantidad exacta

{ stops: { $size: 3 } }

exactamente 3 stops.

"Más de N" (truco)

{ "stops.5": { $exists: true } }

$size no acepta $gt; se pregunta si existe la posición 5 (0-based) → tiene más de 5.

💡 Combinar "contiene X y NO contiene Y" en el mismo campo: { stops: { $all: ["Recoleta"], $nin: ["Plaza Italia"] } }. No repitas la clave stops (la segunda pisa a la primera) — si no, usá $and.

5 · Comparar strings y regex

Por defecto los strings se comparan por igualdad exacta y distinguen mayúsculas. Para coincidencias parciales o por patrón se usa $regex (o la forma corta /patrón/).

Igualdad exacta

{ nombre: "City Tour" }

exacto y case-sensitive. "city tour" no matchea.

Contiene (substring)

{ nombre: { $regex: "Tour" } }
{ nombre: /Tour/ }        // forma corta

incluye "Tour" en cualquier posición.

Empieza / termina con

{ nombre: /^City/ }   // empieza con "City"
{ nombre: /Tour$/ }   // termina con "Tour"

^ = inicio, $ = fin (sintaxis regex).

Sin distinguir mayúsculas

{ nombre: { $regex: "tour", $options: "i" } }
{ nombre: /tour/i }   // forma corta

La opción i = ignore case → matchea "Tour", "TOUR", "tour".

⚙️ Modificadores de cursor (se encadenan al find): .sort({ precio: -1 }) (1 asc, -1 desc) · .limit(n) · .skip(n) · .count(). Ej: db.recorridos.find().sort({ precio: -1 }).limit(3).

6 · $expr — expresiones dentro del filtro

Permite usar expresiones de aggregation dentro de un find/$match. Sirve para lo que el filtro normal no puede: comparar dos campos del mismo documento, o filtrar por un valor calculado.

Comparar dos campos

{ $expr: { $gt: ["$precioVenta", "$precioCosto"] } }

venta mayor a costo. Imposible con el filtro normal (que compara campo vs constante, no campo vs campo).

Filtrar por valor calculado

{ $expr: { $gt: [ { $size: "$stops" }, 5 ] } }

"más de 5 stops": $size se usa como valor. El filtro normal no deja combinar $size con $gt.

⚠️ Sintaxis: dentro de $expr se usa la forma aggregation — operador primero y operandos en array: { $gt: [a, b] }, y los campos con "$campo". Suele no usar índices, así que reservalo para estos casos.

7 · Anatomía de un update

Siempre dos partes: a quién cambiar (filtro) + qué cambiar (operador). db.<coll>.updateOne( <filtro> , <cambio> )

9 · Anatomía de una etapa

Cada etapa es un objeto con un operador de etapa (empieza con $) y su especificación.
{ $group:operador de etapa (qué hace)
{ _id: "$tipo",clave de agrupamiento (por qué campo)
total: { $sum: 1 } } }acumuladores (qué calcular por grupo)

🔑 Referencias a campos: el prefijo $

_id: "$tipo"      // "$tipo" = el VALOR del campo tipo
_id: "tipo"       // "tipo"  = el texto literal "tipo"

Dentro de aggregation, "$campo" significa "el valor de ese campo". Sin $ es un literal.

➕ Acumuladores de $group

$sum  { $sum: 1 }         // contar
$sum  { $sum: "$precio" } // sumar
$avg  { $avg: "$precio" } // promedio
$max / $min / $push

Se aplican por cada grupo que define _id.

11 · ⚠️ Errores comunes — qué NO hacer

MAL db.recorridos.find( precio: 200 )
BIEN db.recorridos.find({ precio: 200 })

El filtro es un objeto: hay que encerrarlo en { }.

MAL { stops: "A", stops: { $ne: "B" } }
BIEN { stops: { $all: ["A"], $nin: ["B"] } }

Clave repetida: la segunda stops pisa a la primera. Combiná operadores o usá $and.

MAL updateOne({…}, { precio: 300 })
BIEN updateOne({…}, { $set: { precio: 300 } })

Sin operador, el update reemplaza el documento entero. Usá $set/$inc/…

MAL { $not: [ { stops: "B" } ] }
BIEN { stops: { $ne: "B" } }

$not no recibe array ni va suelto: envuelve un operador. Para "no contiene", usá $ne.

MAL { totalkm: … } · "recoleta"
BIEN { totalKm: … } · "Recoleta"

Case-sensitive: campos y valores distinguen mayúsculas. Un typo → 0 resultados sin error.

MAL db.recorridos.deleteMany()
BIEN db.recorridos.deleteMany({})

deleteMany/updateMany exigen el filtro. Para "todos" hay que escribir {} a propósito.

🕵️ El más traicionero es el case-sensitive y el nombre de colección mal escrito: MongoDB no tira error, simplemente devuelve 0 resultados. Si algo "no trae nada", revisá mayúsculas y nombres.

12 · find vs aggregate — ¿cuándo cada uno?

Necesito…Uso
Filtrar y traer documentos (o algunos campos)find(filtro, proyección)
Ordenar / limitar una búsqueda simplefind().sort().limit()
Agrupar y calcular (contar, promediar, sumar por grupo)aggregate([ $group ])
"JOIN" con otra colecciónaggregate([ $lookup ])
Desarmar arrays / transformar la forma del documentoaggregate([ $unwind, $project ])
Varios pasos encadenadosaggregate([ ... ])
La estructura en una idea: un find tiene dos objetos — filtro (qué documentos) y proyección (qué campos). Un aggregate es un array de etapas por las que los documentos van pasando y transformándose, donde cada etapa es { $operador: { especificación } }. Regla de oro dentro de aggregation: "$campo" con signo peso = "el valor de ese campo". Si dominás estas dos formas (find de 2 objetos, aggregate de N etapas), podés leer y escribir cualquier consulta.
