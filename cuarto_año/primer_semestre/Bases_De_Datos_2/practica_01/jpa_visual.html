Del objeto Java a la tabla relacional, y el rol de cada capa

1 · Una entidad = un POJO + anotaciones → una tabla

☕ Clase Java (entidad)
@Entity
@Table(name="app_user")
public class User {

  @Id
  @GeneratedValue
  private Long id;

  @Column(nullable=false)
  private String name;

  @Column(unique=true)
  private String email;

  @OneToMany(mappedBy="user")
  private List<Purchase> purchases;
}

@Entity = la clase corresponde a una tabla @Id = clave primaria @Column = columna (con sus restricciones) @OneToMany = relación (FK / JOIN)

2 · Las capas: rol de cada componente

1

Aplicación

Opera sobre objetos: em.persist(user), em.find(User.class, 1L). No incluye SQL.

▼
2

JPA especificación

Define las reglas: interfaces (EntityManager) y anotaciones (@Entity, @Id). Por sí sola no ejecuta nada.

▼
3

Hibernate implementación

El motor concreto. Traduce las operaciones sobre objetos y genera el SQL según el dialecto del motor. Administra el persistence context y el caché.

▼
4

JDBC

La API estándar de bajo nivel. Envía el SQL ya generado a la base por la conexión.

▼
5

Base de datos

PostgreSQL / MySQL / Oracle… ejecuta el SQL y devuelve filas, que Hibernate reconvierte en objetos User.

En síntesis: la aplicación trabaja con objetos y la base de datos con tablas. JPA define cómo describir el puente (anotaciones); Hibernate lo cruza traduciendo objeto ⇄ SQL.

3 · Flujo de una operación: la transformación del dato

Ejemplo: un método que guarda un usuario y luego lo lee. En cada paso el dato adopta una forma distinta.

⬇ Camino de ESCRITURA  ·  objeto → SQL
1 · Aplicación capa de servicio
User u = new User("Ana", "ana@mail.com");   // Transient
em.persist(u);                              // se solicita persistir
objeto Java: User{ id=null, name="Ana", email="ana@mail.com" }
Hibernate lee las anotaciones @Entity/@Column y construye el SQL ▾
2 · Hibernate genera SQL motor
INSERT INTO app_user (name, email) VALUES (?, ?);
sentencia SQL + parámetros ["Ana", "ana@mail.com"]
JDBC envía la sentencia por la conexión ▾
3 · Base de datos RDBMS
-- ejecuta el INSERT y asigna la PK
id=1 | name=Ana | email=ana@mail.com
fila persistida — se genera id = 1
Hibernate recibe el id generado y lo escribe en el objeto ▴ → pasa a Managed
⬆ Camino de LECTURA  ·  SQL → objeto
4 · Aplicación capa de servicio
User u = em.find(User.class, 1L);   // se solicita el id 1
solicitud: el usuario con id 1
Hibernate traduce la consulta a SQL ▾
5 · Hibernate genera SQL motor
SELECT id, name, email FROM app_user WHERE id = 1;
la base de datos devuelve la fila cruda ▾
6 · Base de datos devuelve filas ResultSet
┌────┬──────┬──────────────┐
│ id │ name │ email        │
├────┼──────┼──────────────┤
│ 1  │ Ana  │ ana@mail.com │
└────┴──────┴──────────────┘
datos tabulares (filas y columnas)
Hibernate mapea cada columna a su atributo (hidratación) ▴
7 · Retorno a la aplicación objeto listo
// se obtiene de nuevo un objeto, ya Managed
User{ id=1, name="Ana", email="ana@mail.com" }
objeto Java reconstruido y rastreado por la Session
Constante en todo el flujo: el dato cambia de forma — objeto → SQL → filas → objeto — pero la aplicación solo interactúa con los extremos. La generación de SQL, el envío por JDBC y el mapeo de filas a atributos los realiza Hibernate.
