@GeneratedValue — generación de la clave primaria

Las cuatro estrategias y, sobre todo, cuándo se obtiene el ID: antes o después del INSERT

1 · Qué hace y dónde se declara

@Id
@GeneratedValue(strategy = GenerationType.SEQUENCE)   // ← la estrategia
private Long id;

@GeneratedValue le dice a JPA que no asignás el id a mano: lo genera automáticamente. La estrategia define quién lo genera y cuándo.

2 · Las cuatro estrategias

IDENTITY id: después

Usa una columna autoincremental de la base (AUTO_INCREMENT / SERIAL). La base asigna el id al insertar.

@GeneratedValue(strategy =
   GenerationType.IDENTITY)

SEQUENCE id: antes

Usa un objeto secuencia de la base. Hibernate le pide el próximo número antes de insertar. Ideal en PostgreSQL/Oracle; permite batch.

@GeneratedValue(strategy =
   GenerationType.SEQUENCE)

TABLE id: antes

Emula una secuencia con una tabla auxiliar (hibernate_sequences). 100% portable, pero la más lenta (requiere bloqueo de fila).

@GeneratedValue(strategy =
   GenerationType.TABLE)

AUTO depende

El proveedor elige la estrategia según el dialecto de la base (suele resolver a SEQUENCE o a una tabla). Es el valor por defecto.

@GeneratedValue   // = AUTO

3 · El punto clave: ¿el id viaja antes o después del INSERT?

IDENTITYid DESPUÉS

El id no existe hasta que la fila está insertada → el INSERT se ejecuta ya.

1 · persist(user)

objeto con id = null

2 · INSERT inmediato

INSERT INTO app_user(name) VALUES('Ana') — sin id

3 · la base asigna el id

el AUTO_INCREMENT genera 1

4 · el id vuelve al objeto

Hibernate lee la clave generada → user.id = 1

⚠ No se puede diferir ni agrupar (sin batch inserts).
SEQUENCEid ANTES

Pide el id a la secuencia primero → el INSERT puede esperar al flush.

1 · pedir el próximo id

SELECT nextval('user_seq') → 1

2 · persist(user)

el objeto ya queda con user.id = 1

3 · INSERT (puede diferirse)

INSERT INTO app_user(id,name) VALUES(1,'Ana')

4 · al flush / commit

se manda el INSERT (o varios juntos en batch)

✓ Permite agrupar inserts y optimizar (allocationSize).

La idea del "antes / después": con SEQUENCE (y TABLE) Hibernate consigue el id en una consulta aparte antes de insertar, así que ya puede ponerlo en el objeto y dejar el INSERT para el flush (e incluso juntar varios). Con IDENTITY el id recién existe cuando la fila ya fue insertada, por eso el INSERT se ejecuta de inmediato y no se pueden agrupar. La forma de generar la clave cambia cuándo viaja el dato y, con eso, el rendimiento.
