# 2. Calidad de Software

### Calidad de Producto vs de Proceso ❗
**Producto**: qué tan bien las características del software satisfacen los requisitos. Modelos **ISO/IEC 9126-1** (6 características) y **25010** (8). Evaluación **ISO/IEC 14598** y **25040**.
**Proceso**: grado en que el proceso permite producir software de calidad. Modelo **ISO/IEC 12207**. Evaluación **ISO/IEC 15504** y **33000**.

### Modelo de calidad de producto ❗
**ISO/IEC 9126-1 → 6 características**: Funcionalidad, Confiabilidad, Usabilidad, Eficiencia, Mantenibilidad, Portabilidad.
**ISO/IEC 25010 → 8**: agrega **Seguridad** y **Compatibilidad** (interoperabilidad).

### Calidad de Datos — ISO/IEC 25012 ❗
Capacidad de los datos de satisfacer necesidades bajo condiciones de uso. Dos puntos de vista:
- **Inherentes**: Exactitud, Completitud, Consistencia, Credibilidad, Actualidad.
- **Dependientes del sistema**: Disponibilidad, Portabilidad, Recuperabilidad.

### SGC (Sistema de Gestión de la Calidad) ❗
Sistema basado en **ISO 9001:2015** para asegurar conformidad, satisfacción del cliente y mejora continua.
- **Alcance**: coherente con el contexto, documentado, conciso/específico, exclusiones justificadas, incluye procesos y sedes.
- **Objetivos**: deben ser **SMART** (Específico, Medible, Alcanzable, Relevante, Temporal). *Ejercicio típico: reescribir objetivos mal planteados agregando cuantificación y plazo.*

### Mapa de procesos
Partes: procesos de **Gestión**, **Operativos** y **de Apoyo**, más los **Clientes** (entrada/salida del mapa).

### Métricas de calidad ❗ (ejercicio recurrente)
**Niveles de puntuación**: Rango objetivo · Mínimamente aceptable · Aceptable · Excede los requerimientos (más "Inaceptable").
**Combinar varias métricas → 1 característica (4 niveles)**: ubicar cada métrica en su nivel y combinar; criterio cualitativo → **predomina el peor nivel** (si una es Inaceptable, el resultado es Inaceptable).
**Crear una nueva métrica** (según ISO 9126-2): debe ser **relevante, fiable, válida, objetiva, comprensible**; definir nombre, propósito, fórmula, tipo de medición y los 4 niveles de interpretación.

### Modelo de calidad vs Metodología
Un **modelo** dice **QUÉ** hacer para mejorar (guía la mejora continua), no **CÓMO**. La metodología dice el cómo.

### Otros estándares
**Calidad de servicios** = **ISO/IEC 20000** (proveer servicios de TI según requisitos acordados, calidad consistente).
