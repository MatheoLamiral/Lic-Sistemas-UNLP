1📋 Administración de Proyectos ❗❗

«Planificar y dirigir»: definir el qué, quién y cuánto antes de construir.

🔺 Triángulo de Alcance ❗

Centro: Alcance + Calidad. Lados: Tiempo, Costo, Recursos. Mover un vértice deforma el centro → hay que rebalancear (equilibrio).

📦 Proyecto vs Programa ❗

Proyecto: único, plazo/presupuesto acotado, éxito = cumplir specs. Programa: conjunto de proyectos, éxito = ROI. El proyecto forma parte del programa.

👥 Stakeholders ❗❗

Identificar (Mapa) → Analizar (Matriz de impacto) → Comunicar (Plan: QUÉ/QUIÉN/CUÁNDO/CÓMO).

🗂️ WBS

Descompone el trabajo (Top-Down / Bottom-Up). Tarea sana: acotada, medible, independiente, con entregable. Sin la duración en el nombre.

🏷️ Clasificar proyecto ❗

Por Duración · Riesgo · Complejidad · Tecnología (tipos A→D). Siempre justificar. ítem práctico

📐 Estimación

COCOMO: original (básico/intermedio/avanzado) vs 2.0 (Puntos Objeto, KLOC, P. Función). Esfuerzo: Delphi · 3 puntos (O+4M+P)/6. Duración ≠ Esfuerzo.

…ya planificado, hay que asegurar que salga bien →

2✅ Calidad de Software ❗

«Que esté bien hecho»: el producto y el proceso cumplen lo esperado.

🎯 Producto vs Proceso ❗

Producto (ISO 9126-1 / 25010) · eval. 14598/25040. Proceso (ISO 12207) · eval. 15504/33000.

🧩 Modelo de producto

9126-1 → 6 (Func, Confiab, Usab, Efic, Manten, Portab). 25010 → 8 (+ Seguridad + Compatibilidad).

🗃️ Calidad de Datos 25012 ❗

Inherentes: Exactitud, Completitud, Consistencia, Credibilidad, Actualidad. Dependientes del sistema: Disponibilidad, Portabilidad, Recuperabilidad.

📜 ISO 9001 → software ❗❗

Se aplica usando ISO/IEC 90003:2018 como directriz. respuesta fija

🏛️ SGC

Base ISO 9001:2015. Alcance documentado/conciso + Objetivos SMART (Específico, Medible, Alcanzable, Relevante, Temporal).

📊 Métricas en 4 niveles ❗

Combinar varias → predomina el peor nivel. Crear nueva → relevante, fiable, válida, objetiva, comprensible.

…¿y quién controla que todo esto se cumpla? →

3🔍 Auditoría de Sistemas ❗

«Verificar y controlar»: evidencia para confiar en el sistema y sus datos.

📖 Definición + 4 objetivos ❗

Recolectar/evaluar evidencia para: preservar activos, integridad de datos, eficiencia de recursos, eficacia de objetivos.

⚖️ Opinión del auditor ❗❗

Sin calif. (todo ok) · Con calif. (pérdidas no graves) · Adversa (pérdidas graves) · Excusada (no puede opinar).

🎲 Riesgos de auditoría

Inherente (propio) · De control (falla el control) · De detección (el auditor no lo ve).

🛡️ Controles ❗

Preventivo (antes, ej. validar campo) · Detectivo (después, ej. log) · Correctivo (corrige, ej. reset). «Un control es un sistema».

🏢 Gobernanza vs Adm. de TI ❗

Gobernanza: QUIÉN decide (Evaluar/Dirigir/Monitorear). Administración: ejecuta (Planificar/Construir/Ejecutar/Monitorear).

📐 COBIT

Marco de ISACA. Separa gobernanza de administración. 5 principios · 37 procesos (dominios: APO/BAI/DSS/MEA).

💻 Abuso informático

vs fraude comercial: se diferencia por Escalabilidad (masivo) y Trazabilidad (deja logs).

… atravesando todo el proyecto ↓

🤝 4 · Capa transversal: Colaboración & Interfaces (cae poco — definición + ejemplos)

🌐 Sistemas Colaborativos

Permiten trabajar en conjunto. Interacción sincrónica/asincrónica y mismo lugar/distribuido. Tipos: Wikis, Foros, Repositorios, Mail.

✋ Interfaces no convencionales

Hápticas (tacto/fuerza): guante VR, volante con force-feedback, cinturón con vibración. También voz, gestos, RA/RV.

🧠 Truco mnemotécnico del flujo: Planifico (Proyectos) → Construyo con Calidad → Audito → todo sobre una base de Colaboración. → «P-C-A-C».
